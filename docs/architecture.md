# Luigi Tools 架构

状态：拆仓后的实施基线。更新日期：2026-10-22。

本仓库只维护统一 CLI；Skills、UI 和项目模板分别在独立仓库维护、构建和验证。产品业务继续留在各自产品仓库。不建设插件平台、账号系统、后端目录服务或自研 MCP。

## 仓库边界

| 仓库           | 维护内容                                           | 分发产物                              |
| -------------- | -------------------------------------------------- | ------------------------------------- |
| luigi-tools    | 参数、交互、目录解析、依赖解析、安装事务、doctor   | npm 包 @luigix/tools，命令 lt         |
| luigi-ui       | 定制 UI 组件、主题和相关验证                       | registry/index.json 与独立资产快照    |
| luigi-skills   | SKILL.md、references/scripts/assets 和 Python 测试 | registry/index.json 与独立 Skill 快照 |
| luigi-starters | 模板、GitHub 和 code-quality 预设、组合依赖        | registry/index.json 与独立资产快照    |

CLI 不导入其他仓库源码，不要求用户安装 Git 或克隆整个仓库。各内容仓库保留自己的锁文件、检查命令和 CI。维护者在内容仓库构建分发文件并随源码提交；不设置自动提交或自动发布。

当前仓库为单包项目，只有根目录一份 package.json。pnpm-workspace.yaml 仅配置 esbuild 的依赖构建权限，没有 packages 子包声明。仓库结构：

```text
src/               CLI 业务逻辑
test/              安装与来源协议回归测试
scripts/           质量检查与 smoke
tooling/           本仓库使用的工程工具副本
docs/              CLI 架构、协议与规范
sources.json       默认公开索引地址
package.json       开发脚本、依赖与 npm 发布配置
tsconfig.build.json CLI 构建配置
```

本仓库的 tooling 和编码规范是消费者配置；可分发的 code-quality 预设归 luigi-starters 维护，两者不通过相对路径互相导入。最小 v1 夹具验证旧协议安装行为，不维护产品内容。默认 smoke 将该夹具转换为 v2 索引和独立快照，验证当前协议。

## 安装链路

1. 解析命令；交互仅补齐输入。非交互写入缺少 `--cwd` 时立即失败。
2. 读取本地或 HTTPS 索引。`--source` 优先于 `LT_SOURCE`，未指定则使用包内 sources.json。
3. `list` 和选择菜单只使用元数据；相同资产展示最高的稳定数字版本。
4. 解析所选资产及其固定版本依赖，拒绝缺失、循环、重名版本和同一安装中的版本冲突。
5. 逐个下载必要快照，核对摘要、身份、版本、文件路径和文件内容摘要。其他资产正文不下载。
6. 全部内容验证通过后，复用现有项目锁、冲突检查和文件事务，统一写入，不保存持久安装记录。
7. `init` 在资产事务完成后，按明确选择调用 npm/pnpm；失败保留项目与安装中间文件，显性报告重试方法。

只有模板可以组合 Skills。模板声明精确依赖，不再安装目录中的所有 Skills。Skill 本身自包含；UI 和预设可依赖 UI/预设；不支持模板嵌套。

## 版本与来源

CLI、UI、Skill、预设和模板可以独立发布。v2 资产版本使用 `major.minor.patch`，不引入版本范围或 prerelease 解算器。`add` 默认选择索引中的最高版本；模板依赖精确匹配指定版本。

索引保留历史版本，正文采用 SHA-256 命名。构建脚本拒绝覆盖同名同版本的不同内容；修改内容或依赖需提升对应资产版本。新 UI 版本不会自动改变现有模板依赖。

多来源配置只组合一层索引，不允许递归包含。`--source-sha256` 对单索引校验原始字节摘要；对组合配置校验配置与各子索引摘要组成的确定性摘要，因此能检测任何子索引漂移。摘要不证明发布者身份。

默认主分支索引用于发现新版本。需要长期复现时使用固定 commit 地址的来源配置，并固定其中每个子索引地址或摘要；复用命令附带组合摘要，来源漂移时显性失败。正文地址及摘要仅用于本次校验，不写入安装记录。

来源下载仅允许 HTTPS 或本地文件；拒绝远程索引引用 file 等协议。HTTPS 请求不跟随重定向，每次超时 15 秒，连接重置、临时 DNS 故障、超时及 HTTP 408/429/500/502/503/504 总共最多尝试 5 次，按 250、500、1000、2000 毫秒退避；校验错误不重试，单响应最大 2 MB；一次安装最多 100 个资产，文件正文合计最多 20 MB。仅支持 UTF-8 文本文件，不执行下载的脚本。首次安装联网，本地来源与 doctor 支持离线。

## 文件保护与兼容

不创建或读取 `.agent-base`，不保存替代的持久 manifest。保留 v1 完整目录读取能力，旧目录依然按原约定初始化全部 Skills。

- `--dry-run` 可以读取/下载并检查计划，但零落盘，不调用包管理器。
- Skill 按实际 SKILL.md 的 name 识别，同名已存在就跳过，保留本地定制。无有效 Skill 的同名目录显性冲突。
- UI/模板/预设的全部目标文件与来源内容一致时重复安装为 no-op，部分存在或内容不同则整批拒绝。
- 不隐式覆盖、不提供 force。拒绝路径穿越、保留目录、符号链接、大小写碰撞及目录/文件碰撞。
- 写入使用临时 `.lt-install.lock`；成功或失败后清理，失败回滚本次新增内容，清理失败显性报告。
- doctor 只检查实际 Skill 元数据、现存目录缺少 SKILL.md 及残留锁，不校验历史版本、正文或附属资源差异，不自动抢锁。
- 断电、强制结束及外部并发改文件可能留下部分文件；不保存基线，需人工检查实际状态。

Skills 安装在项目的 `.agents/skills` 或 `.claude/skills`，不修改全局配置。不创建远程 Issue、不初始化业务项目 Git、不提交或部署。

## 验证

`pnpm check` 完成 lint、只读格式检查、类型检查、测试与构建。测试覆盖旧协议兼容、按需下载、版本固定、跨来源依赖、错误输入、冲突保护、事务回滚、目录选择和依赖安装行为。

`pnpm smoke` 在仓库外安装 npm 包并验证命令入口，确认分发包不含资产正文。默认使用最小 v2 夹具验证按需下载、文件一致性、重复安装保护、doctor，以及 npm/pnpm 真实依赖安装；`LT_SOURCE` 指向真实内容索引时联调跨仓安装并运行模板 check 脚本。

UI、Skill 和模板的内容验证归对应仓库。UI 类型验证不能替代浏览器交互和无障碍检查；迁移不宣称新增了浏览器验证。
